# d 总体架构设计

## 一、定位与设计原则

`d` 是一个使用 Rust 构建的通用可扩展网络守护进程（Daemon）。

它既可以承担高并发线上网关、静态托管与反向代理职责，也可以通过按需装配开发工作流提效扩展，服务于现代应用与流式交互的日常编码、联调与预览。在 `d` 的产品定义中，不设“生产模式”与“开发模式”的二元之分——用户的开发环境本身就是 `d` 的核心正式生产场景之一，与线上服务遵循完全一致的架构质量、可靠性与生命周期标准。除内置的文件服务与内容展示能力外，任何依赖网络通信、HTTP、WebSocket 或原生 TCP 的业务形态——包括文件与文档库、音视频与音乐流服务、实时聊天与 IM 服务、AI 应用与智能体服务、通用代理与流量网关——都可以作为应用模块按插件方式直接挂载到 `d` 之上。

整体架构遵循四项核心原则：

1. **底层自控、极简依赖、高自由度与高效率**
   网络传输接入、协议状态机、路由匹配、过滤管线、文档渲染、代码语法高亮与界面资源均优先基于 Rust 标准库、基础系统调用与极少量的基本底层库自建内建，不绑定重型上层框架；浏览器前端页面实现 100% 离线自包含、零外部资源链接。
2. **静态契约隔离与动态时空组合并重**
   源码组织上坚持契约与实现分离、入口壳与装配清单分离，禁止实现组件之间跨边界直接耦合；运行时采用细粒度响应式微内核管理控制面生命周期，同时通过不可变快照与数据面完全解耦，兼顾动态热插拔灵活性与生产级吞吐。
3. **独立抽象、可拆可复**
   一切可从具体网络应用剥离的基础机制（如插件生命周期微内核、传输监管与连接排空、底层协议引擎、内建文档与高亮渲染、文件服务与展示层）均抽象为独立包并保持零上层业务污染，可独立演进、独立开源发布并在其他系统中直接复用。
4. **单一演进、无历史包袱**
   不引入内部版本分支，不保留失效旧路径与冗余兼容包装，所有架构演进直接收口到当前确认的唯一结构与正式契约。

## 二、五层垂直架构总览

系统自底向上划分为五个严格单向依赖的层次：上层仅依赖下层暴露的接口契约，禁止逆向依赖或同层内部实现直连。

```text
+-----------------------------------------------------------------------+
|  装配产物层（Assemblies）                                              |
|  通用版 `d` · 按场景裁剪的网关 / 文件托管 / 开发工作流提效装配产物       |
+-----------------------------------------------------------------------+
|  纯入口壳（Entries）                                                   |
|  命令行参数解析 · 配置文件接入 · 系统信号桥接 · 守护进程启动              |
+-----------------------------------------------------------------------+
|  第 4 层 · 应用层（Mounted Applications）                              |
|  文件服务器 + 展示层（文档/代码/媒体） · 音乐流 · IM · AI 应用网关       |
+-----------------------------------------------------------------------+
|  第 3 层 · 能力扩展层（Extensions，作为框架层插件接入）                 |
|  流量治理与线上服务：L7/L4 反代 · 负载均衡 · 流式压缩 · CORS · 鉴权 · 限流 · 指标 |
|  开发工作流提效：本地自动 HTTPS · 聚合反代 · 接口模拟 · 实时刷新 · 流式检视器 |
+-----------------------------------------------------------------------+
|  第 2 层 · 协议引擎层（Protocol Engines，挂载于第 1 层传输内核）         |
|  自建底层 HTTP 引擎 · WebSocket 引擎 · 原生 TCP / 自定义流式协议引擎     |
+-----------------------------------------------------------------------+
|  第 1 层 · 守护进程与传输核心层（L4 Core）                              |
|  Listener 监管 · TLS / SNI / ALPN · 连接跟踪与优雅排空 · 热加载协调器   |
+=======================================================================+
|  第 0 层 · 框架层（独立通用插件微内核包 `d-frame`，`crates/frame`）      |
|  Context · Scope · Service · Fiber · Effect · Event · Loader · Inspect |
+-----------------------------------------------------------------------+
```

### 第 0 层 · 框架层（独立通用插件微内核）

框架层是完全独立的通用运行时微内核，**不包含任何网络协议、文件系统或业务语义**，只解决两类根本问题：模块之间的**空间组合（按作用域声明与解析服务依赖）**与**时间组合（按生命周期完整获取与逆序回收一切资源副作用）**。

核心原语如下：

1. **上下文与作用域隔离（`Context` / `Scope`）**
   - `Context` 是插件运行与通信的统一表面，承载所属纤程、服务解析入口、事件通道、效应登记与子作用域派生。
   - 通过 `isolate` 创建隔离作用域，子作用域可局部覆盖特定服务实现（例如为不同虚拟主机、不同端口或不同租户挂载各自的路由器与日志输出器），未隔离的服务自动沿父作用域向上继承。
2. **强类型服务（`Service`）**
   - 以静态类型键与稳定诊断名注册和读取服务，解析结果返回只读共享句柄，避免动态字符串的隐式错配与运行时反射开销。
   - 同一隔离域内同类型服务仅允许存在一个提供者，重复提供立即报错；提供者可附带可选就绪检查条件，只有通过就绪检查的服务才对依赖方可见。
3. **响应式纤程状态机（`Fiber`）**
   - 每个插件实例或应用挂载单元均由一条纤程管理，状态严格在以下枚举间流转：
     `Pending → Loading → Active → Unloading → Failed / Disposed`。
   - 插件显式声明所依赖的服务集合。缺少依赖时，纤程停留在 `Pending` 等待而非报错崩溃；所有依赖就绪后自动进入激活流程；**一旦任一依赖提供者卸载或被替换，所有消费该服务的纤程会自动级联卸载，并在新提供者就绪后自动重建**，确保运行中的插件永远不会持有已失效的陈旧服务引用。
4. **异步资源效应与结构化回收（`Effect`）**
   - 系统内一切运行时副作用——绑定端口、注册路由、挂载过滤器、订阅事件、启动文件监听或定时器、建立上游连接池——都必须通过 `effect` 登记并归属于特定纤程。
   - 所有权在资源获取执行前预先登记，支持任意层级嵌套、初始化中途失败时自动按逆序回滚已获取部分、幂等重复释放以及结构化并发合流（多次并发触发清理共享同一异步收尾过程）。
   - 清理顺序遵循严格约束：同一效应内部收集的清理步骤按**后进先出（LIFO）逆序串行**释放；彼此独立的兄弟效应可并发释放以缩短停机或重载耗时。
5. **强类型事件总线（`Event`）**
   - 事件由强类型载荷定义，监听器的注册本身就是一条受纤程托管的效应，纤程卸载时监听自动摘除。
   - 提供四种调度语义以满足控制面与扩展链需求：
     - `emit`：同步顺序广播通知；
     - `parallel`：异步并发执行全部监听器并聚合异常；
     - `serial` / `bail`：按优先级依次执行并在首个返回有效结果时短路中止，适用于路由插件匹配、请求拦截或展示器抢占；
     - `waterfall`：责任链式嵌套组合，允许前置处理器拦截、改写或中止配置更新与动作传递。
6. **声明式装配器与热更新（`Loader`）**
   - 从结构化配置清单驱动插件树的增量编排：在触碰任何运行中纤程之前，先对完整候选配置执行全量预检（preflight）与约束校验；任意节点校验失败即整体拒载，保持线上原有拓扑不受影响。
   - 校验通过后按稳定节点标识序列化对比（diff）更新运行树：仅配置字段变化的节点执行局部热更新；被移除或禁用的节点卸载其效应树；实现体或隔离配置发生变更的节点先完整卸载旧纤程再挂载新纤程。
   - 默认通过编译期静态工厂注册表将配置标识映射为原生组件，确保单二进制零动态链接风险与最高执行效率；同时保留可扩展的模块解析器接口，以便未来按需接入外部安全沙箱模块。
7. **脱敏拓扑检视（`Inspect`）**
   - 输出当前全部纤程的只读运行视图：纤程唯一标识、名称、当前状态、声明依赖列表、活跃效应计数与截断后的错误摘要；结构化设计上绝不回传配置原文、密钥或凭据内容。

### 第 1 层 · 守护进程与传输核心层（L4 Core）

第 1 层是面向操作系统的网络传输宿主，负责把底层套接字、加密握手、连接寿命与进程信号纳入统一监管，不感知上层具体跑的是 HTTP、WebSocket 还是自定义 TCP 协议：

- **Listener 与传输抽象**：统一抽象 TCP 监听、Unix Domain Socket 接入以及后续的 UDP 与传输层安全（TLS 终止、基于 SNI 与 ALPN 的多协议透明分流）。监听绑定动作作为框架层效应受管，支持多端口、多地址并行运行与独立启停。
- **连接监管与优雅排空（Graceful Drain）**：内部维护活跃连接台账与关联协议类型。在收到停机信号或配置触发监听重建时，第一时间关闭新连接接收，对短请求连接等待当前处理完成，对长连接（如 WebSocket、流式响应、自定义 TCP 会话）下发温和排空通知并在可配置硬超时窗口后收尾，既不粗暴断流，也不让进程无限挂起。
- **信号与热加载协调**：监听 `SIGINT` / `SIGTERM` 与配置重载事件，协调声明式装配器与传输核心按序切换；同时向容器与进程管理器提供存活（Liveness）与就绪（Readiness）状态探针。

### 第 2 层 · 协议引擎层（Protocol Engines）

所有协议引擎均以独立组件形态作为插件挂载到第 1 层之上，底层直接基于异步字节流与自有协议解析/序列化状态机实现，不依赖重型第三方 Web 框架，从而在零拷贝、内存布局、长连接控制与流式语义上拥有完全的自由度：

1. **自建底层 HTTP 引擎**
   - **原生协议处理**：直接面向异步字节流实现严谨的请求行、头部字段解析、持久连接复用（Keep-Alive）、分块传输编码（Chunked）、预期校验与响应流式写出（HTTP/1.1 起步，协议状态机与帧边界清晰解耦以平滑演进至 HTTP/2 与 HTTP/3）。
   - **控制面与数据面严格分离**：
     - **控制面**：应用与扩展通过框架层 `Effect` 向引擎注册虚拟主机（Host）、路径匹配规则（精确 / 前缀 / 模式）、请求前过滤器与响应后过滤器；插件卸载即自动撤销对应规则。
     - **数据面**：每当控制面发生有效增删改时，引擎将当前生效的路由表与过滤链编译为一份只读不可变执行快照，通过无锁原子指针交换发布给工作线程。每个入站 HTTP 请求只执行一次无锁原子读并沿不可变快照直通处理，请求热路径无动态服务查找、无全局互斥锁争用。
   - **流式一等公民**：请求与响应体原生采用增量字节流抽象，非全量缓冲。针对 `text/event-stream`（SSE）与大文件流等场景，提供显式流式上下文标记，自动抑制沿途可能破坏实时性的全量缓冲与整包压缩行为。
2. **WebSocket 引擎**
   - 依托 HTTP 协议升级握手转入全双工帧通道，内置读写分离、控制帧（Ping / Pong / Close）自动处理、发送队列背压控制与停机排空通知，供聊天/IM、实时协作面板与开发期热刷新共用。
3. **原生 TCP / 流式协议引擎**
   - 直接消费第 1 层原始字节流或 TLS 解密流，提供帧切分辅助、空闲超时与四层透传原语，为后续自定义二进制协议（如专用即时通讯协议、私有 RPC 或四层端口转发）保留无损入口。

### 第 3 层 · 能力扩展层（Extensions）

横切非业务能力全部以框架层插件方式挂载，借由协议引擎暴露的过滤器管线与上下文挂钩介入请求生命周期：

#### 1. 流量治理与线上服务扩展

- **反向代理与上游调度（L7 / L4）**：支持路径改写、请求头/转发头（`Forwarded` / `X-Forwarded-*`）注入、多上游目标池管理、连接复用池、负载均衡策略及主被动健康检查；原生支持流式响应（SSE）与 WebSocket 升级隧道的零缓冲透传。
- **流式感知响应压缩**：支持 `gzip`、`deflate`、`brotli` 协商压缩，且自动跳过已压缩媒体格式、分片范围响应（`206`）以及实时事件流（`text/event-stream`），杜绝“开压缩导致 AI 输出卡死”的经典陷阱。
- **跨源访问控制（CORS）**：保持默认关闭（同源安全优先），开启后按规则响应预检请求与跨源响应头。
- **访问观测与治理**：结构化访问日志、运行时指标采集、限流与熔断、访问鉴权（基础认证 / 令牌校验 / IP 策略）以及自动 TLS 证书签发续期。

#### 2. 开发工作流提效扩展

面向开发工作流的能力扩展不是与核心混写在一起的“临时调试开关”，而是与流量治理扩展地位完全对等的一等正式插件：

- **本地自动 HTTPS**：自动生成并管理本地受信任根证书与本地域名证书，并透传正确的协议头给后端应用，彻底消除本地开发因协议不一致导致的混合内容拦截、Cookie 失效或跳转循环。
- **多服务聚合反代与接口模拟（Mock）**：一条精简配置即可同时挂载本地静态文件根目录、将业务接口前缀反代到本地后端进程、为未完成接口提供本地模拟响应，无需再为本地联调额外堆砌多层代理工具。
- **零外链文件监听与自动刷新（Live Reload）**：监听静态资源与文档目录变更，通过内建 WebSocket 通道向页面推送刷新通知（刷新脚本由本机服务内联提供，不引入任何外部脚本）。
- **实时请求与流式检视器**：提供统一白底检视页面，除查看常规 HTTP 请求头/响应体/耗时并支持一键重放外，专门针对现代 AI 与实时应用提供 **SSE 逐块到达时间线** 与 **WebSocket 双向帧记录**，解决传统代理面对长流响应“长时间挂起看不到分片”的痛点。
- **细粒度热更不杀长连接**：得益于第 0 层框架的纤程隔离，用户调整静态目录规则或某个接口模拟配置时，仅卸载并重建对应分支纤程，正在传输中的 AI 流式对话或 IM WebSocket 会话完全不受波及。

### 第 4 层 · 应用层（Mounted Applications）

应用层由真正面向用户或业务提供功能的模块组成。所有应用只依赖第 0 层框架原语与第 2 层/第 3 层暴露的协议契约，彼此保持完全隔离：

1. **文件服务器与内容展示应用（当前核心主应用）**
   - **安全与路径规范**：严格执行请求路径解码、词法清洗、工作目录真实路径校验及符号链接越界拦截（越界统一返回 `404`，不泄露目标存在性）；访问不带末尾 `/` 的目录时自动规范化重定向至带 `/` 路径，保证相对链接与文档内相对图片地址解析正确。
   - **完整静态文件协议语义**：流式分片读取文件（内存占用恒定与文件体积无关）；完整支持单段/后缀/开放式字节范围请求（`Range` 返回 `206`、越界返回 `416`）、强/弱 `ETag` 与 `If-None-Match`、`Last-Modified` 与 `If-Modified-Since` 条件请求（`304`）、`HEAD` 响应及符合规范的附件下载文件名编码。
   - **目录服务**：存在 `index.html` 时默认直接托管静态站点（附带路径安全校验），通过 `?listing=true` 可切回目录视图；支持多维度排序（名称、大小、修改时间、类型）与权限受控的隐藏文件切换开关。
   - **可插拔展示层**：文件应用暴露展示器注册表服务；Markdown、代码、文本、图片、音频、视频等各类展示器均作为独立插件注册自己负责的文件类型与渲染处理，后续扩充新格式（如结构化表格、其他笔记格式）无需修改文件核心逻辑。
2. **多形态网络应用扩展范式**
   - **音乐与媒体流服务器**：直接挂载文件流服务与媒体元数据索引插件，天然复用 `Range` 分片拖动与连接排空能力。
   - **聊天与 IM 服务器**：通过第 2 层 WebSocket 引擎或原生 TCP 引擎接入会话房间与消息广播插件，会话状态绑定为受管效应，支持优雅下线通知。
   - **AI 应用与智能体服务**：挂载基于 SSE 流式 HTTP 引擎与 WebSocket 引擎的会话处理器、工具路由与反向代理上游池，并由第 3 层流式压缩豁免与限流扩展协同保护。

## 三、工作区物理组织与可独立发布包矩阵

为确保各层依赖边界靠编译器强制保证（而非仅靠约定），整个仓库按契约、实现、入口与装配四个职责区组织：

```text
workspace/                          # 32 个 Workspace 包（其中 19 个零外部依赖纯包）
├── Cargo.toml                      # 纯 Virtual Workspace 与 [workspace.metadata.architecture]
├── crates/
│   ├── frame/                      # 第 0 层：独立微内核包（纯 std 零外部依赖）
│   ├── contracts/                  # 7 个纯接口契约包（Trait、ScopedService 视图与共享数据类型）
│   │   ├── net-api/                #   L4 传输、多监听选项与连接生命周期契约
│   │   ├── tls-api/                #   TLS 握手、SNI/ALPN 协商与热换证契约
```

### 可独立沉淀与公开发布的包矩阵

以下组件在设计上保持纯正通用性，达到稳定边界后均可直接拆出或单独发布供外部项目复用：

1. **框架层微内核包（`frame`）**：纯 Rust 零外依响应式插件与异步资源生命周期微内核，适用于守护进程、桌面后端、CLI 插件宿主机及各类动态组合系统。
2. **守护进程传输与 TLS 包（`l4-transport` + `l4-tls` + `net-api`/`tls-api`）**：通用的多地址监听、连接上限与统计、分阶段优雅排空、纯 Rust SNI/ALPN 与零断连热换证核心。
3. **底层 HTTP/WS/TCP 引擎包（`proto-http` + `proto-ws` + `proto-tcp` + `http-api`/`ws-api`）**：控制面与数据面分离、无锁不可变快照路由、流式零缓冲优先、RFC 6455 与原生 TCP 的轻量底层协议引擎。
4. **内建文档与词法高亮包（`doc-render` / `doc-render-plain` + `render-api`）**：零外部脚本、零网络请求、静态编译内建的 Markdown（含嵌入式 HTML 与可选净化）及多语言轻量语法高亮库，并附带纯文本安全转义替代实现 `doc-render-plain` 实证同契约可互换。
5. **文件与展示引擎包（`app-files` + `viewer-*`）**：即插即用的白底安全多挂载静态文件托管与可插拔内容浏览套件。
6. **通用反向代理、治理与开发提效包（`ext-proxy`、`ext-observability`、`ext-ratelimit`、`ext-auth`、`ext-dev-kit`）**：面向现代 AI 流式与线上/本地联调统一场景的代理、纯 `std` 治理及开发增强套件。
7. **`d` 与 `d-minimal` 宿主发行版、可选 `d-mcp`、`skills/` 与 `xtask` 工具链**：基于组件无关 `d-daemon` 底座与 `Loader` 声明式装配出全栈 `d`（默认带可选开关关闭状态的 `mcp` 特性）与轻量 `d-minimal`（支持 `--features mcp`）；结合组件 `Plugin::schema()` 自描述、`d-mcp` 动态自省工具与 `skills/{d,d-dev}`，令运行控管能力随新组件自动演进，并由 `cargo xtask check/info/test` 强制架构与 Skill 完整性。

## 四、当前阶段重点体验升级：完善 Markdown、零外链与极简白色界面

在搭建新架构的过程中，现有产品体验同步完成以下三项核心升级，彻底改变以往依赖外网脚本、深色重装饰和静态 Markdown 残缺的问题。

### 1. 完善的纯内建 Markdown 渲染

- **完全服务端解析与渲染**：在纯 Rust 服务端将 Markdown 直接编译为完整语义 HTML，彻底移除所有外部脚本与远程样式表引用，离线内网环境 100% 可用，消除浏览器端二次解析闪烁。
- **完整规范与扩展能力**：
  - 完整支持标准通用语法与扩展格式（多级标题、列表与嵌套列表、任务列表复选框、表格与对齐、引用块、分割线、删除线、脚注、自动链接、定义引用、行内代码与围栏代码块）。
  - 为各级标题自动生成稳定唯一的锚点标识（兼容中英文与标点），支持页内 `#anchor` 直接跳转。
- **原生支持嵌入式 HTML**：
  - 停止对 Markdown 原文做整体转义后交给脚本解析的做法；在解析事件流中直接保留块级与行内嵌入式 HTML（如 `<details>`、`<summary>`、`<figure>`、`<figcaption>`、`<img>`、`<table>`、`<video>`、`<audio>`、`<kbd>`、`<div>`、内联排版属性等），使工程文档常见的图文混排、折叠说明、多栏表格能够完整渲染。
  - 默认策略面向本地与可信根目录完整透传嵌入式 HTML；开启 `sanitize_html: true` 时启用纯 Rust 内建严格白名单净化（标签与属性白名单、引号感知扫描、URI HTML 实体解码与危险标签未闭合截断），同时保留 `MarkdownOptions::sanitizer` 自定义钩子。
- **图片显示与相对路径保障**：
  - 支持标准相对路径图片（`./img.png`、`assets/diagram.svg`、`../shared/pic.webp`）、根相对路径图片（`/assets/logo.png`）、外链图片以及嵌入式 HTML `<img>` 标签。
  - 配合目录路径末尾 `/` 自动规范化重定向，彻底杜绝无尾斜杠访问目录或文档时相对图片路径基准错位的问题；图片默认采用自适应宽度展示（`max-width: 100%; height: auto;`），保证大图不撑破版面，并支持点击直达原始图片。

### 2. 无冲突的内容与媒体路由约定

为了保证页面内嵌资源、静态网站、命令行下载与浏览器可视化预览之间永不互相打架，严格执行以下路由契约：

| 资源类别 | 默认裸路径行为（`/path/to/file`） | 显式参数行为 |
| :--- | :--- | :--- |
| **图片、音频、视频、样式、脚本、字体、二进制文件** | **直接返回原始字节流**（附带准确内容类型、`Range`、`ETag`），保证 `<img src>`、`<video src>`、静态网页引用与命令行抓取 100% 稳定 | `?view=viewer` 打开白底媒体展示页（页内标签直连裸路径，天然支持拖动进度）；`?view=download` 强制触发附件下载 |
| **文档与代码文件（`.md`、源码、配置、纯文本等）** | **返回统一白底极简展示页**（浏览器打开即读）；Markdown 直接呈现渲染视图，源码呈现服务端高亮视图 | `?view=raw` 返回纯文本原始字节流；`?view=preview` 返回纯预览正文；`?view=download` 触发下载 |
| **目录（`/dir/`）** | 存在有效沙箱内 `index.html` 时直出首页，否则返回极简白底目录索引；无尾斜杠自动重定向补 `/` | `?listing=true` 跳过 `index.html` 强行查看目录；`?sort=` 与 `?hidden=` 控制排序与隐藏项 |

### 3. 内建轻量语法高亮

- 放弃外部高亮脚本与庞大语法描述文件包，采用内建纯 Rust 轻量词法扫描引擎直接生成语义化标签与内置浅色配色表，覆盖系统编程、脚本语言、配置标记与查询语言等常用格式。
- 代码块与单独的源码查看页共用同一套高亮实现与样式表，输出体积小、渲染零延迟、样式完全可控。

### 4. 极简白色视觉体系

全面清除原有的深色背景、五颜六色文件类型标签、emoji 符号堆砌和厚重卡片嵌套，全站统一为克制、清爽的白底纸面排版：

- **色彩基调**：
  - 主画布：纯白 `#ffffff`
  - 辅助底色（代码块、表格表头、极简顶栏）：极浅灰 `#f6f8fa`
  - 分割线与细边框：冷灰 `#e5e7eb`
  - 主正文：深炭黑 `#1f2328`
  - 次要元信息（大小、时间、路径分隔）：中性灰 `#656d76`
  - 唯一强调色（链接、当前激活态）：克制蓝 `#0969da`
- **布局与减法**：
  - 去掉所有 emoji 与花哨彩色胶囊徽标；文件类型通过文件名后缀和极淡素色单线符号或纯文本微标识区隔，视觉焦点完全还给文件名与内容本身。
  - **目录页**：顶部收敛为单行极简信息条（当前面包屑路径 + 轻量化排序与隐藏切换链接）；下方是一体化细线表格（目录名保留 `/` 标识且排在文件前，列对齐为名称、大小、修改时间），页脚仅一行精炼统计。
  - **文档与媒体查看页**：顶部单行低存在感工具栏（`← 返回目录`、文件名与元信息、`Preview | Raw | Download` 扁平切换）；正文区取消重边框外框，Markdown 采用约 `820px` 居中阅读栏宽、宽松行高（`1.7`）、清晰标题层级与左侧浅灰细线引用块；图片/音频/视频查看页在白底中央干净呈现媒体本体与基础尺寸/格式信息。

## 五、多场景组合装配策略（无模式割裂）

`d` 不设置所谓的“生产模式”与“开发模式”的内部切换。对于 `d` 而言，无论是部署在公网节点承担反向代理与静态托管，还是运行在工程师本机支撑高频编码联调、文档预览与 AI 流式调试，**两者同属 `d` 的正式生产应用场景**，共享同一套底层引擎、同一套生命周期与热更新安全保证，代码内不存在任何特殊环境判断分支。

不同使用场景之间的差异，完全通过**静态装配选择**（决定编入哪些包）与**运行期声明式组合**（决定加载哪些扩展插件）来表达，且各类扩展可以自由混搭：

| 组合维度 | 流量治理与线上服务场景 | 开发工作流提效场景 |
| :--- | :--- | :--- |
| **装配与裁剪** | 仅编入核心、协议、流量治理扩展与目标业务应用，保持最小二进制体积与最小暴露面 | 编入同一套核心与协议层，按需叠加开发工作流提效扩展（也可与流量治理扩展同进程混装） |
| **传输与安全** | 标准 TLS 终止与证书自动续期、严格访问控制与来源策略 | 一键签发受信任本地 HTTPS 证书并自动补齐转发协议头 |
| **流量与路由** | L7/L4 反向代理、连接池、负载均衡、主被动健康检查、限流熔断 | 多服务本地聚合反代 + 局部接口模拟（Mock），消除跨域与多端口碎片 |
| **流式与实时** | 流式感知压缩、长连接优雅排空超时控制 | 零外链实时刷新（Live Reload）+ SSE / WebSocket 逐帧实时检视器 |
| **重载与可观测** | 脱敏拓扑检视；配置全量预检，失败整体拒载，线上零闪断 | 同等细粒度纤程热更：局部调整挂载或模拟规则时不中断在途 AI 流式会话 |

## 六、分阶段落地路线

每阶段坚持单一正式实现、完整验收闭环与及时清理中间产物的原则推进：

1. **阶段 1：抽离并立稳框架层独立包**
   - 确定最终公开包名并建立独立包边界，实现 `Context`、`Scope`、`Service`、`Fiber`、`Effect`、`Event`、`Loader` 与 `Inspect`；
   - 通过全套生命周期边界测试（依赖动态到达/丢失/替换、异步效应逆序回滚与并发 join、作用域隔离、配置预检与增量 diff、脱敏检视）。
2. **阶段 2：搭建传输核心与自建底层 HTTP 引擎，重构 `d` 为分层工作区**
   - 落地契约/组件/入口/装配工作区骨架，接入框架层底座；
   - 实现第 1 层传输监管与优雅排空，实现第 2 层自建底层 HTTP 状态机、无锁快照路由与过滤器管线；
   - 将现有文件服务迁入第 4 层应用，压缩与 CORS 下沉为第 3 层标准扩展，同步补齐目录尾斜杠重定向，并保持全部既有命令行参数、集成测试与端到端 HTTP 验收通过。
3. **阶段 3：交付极简白色界面、完善内建 Markdown、词法高亮与媒体展示层**
   - 实现 `doc-render`（完整 Markdown + 图片相对路径 + 嵌入式 HTML 透传 + 锚点 + 纯 Rust 轻量词法高亮），彻底移除所有外部资源链接；
   - 全面切换为极简白色设计体系，落地 `viewer-markdown`、`viewer-code`、`viewer-media`（图片/音视频 `?view=viewer`）与规范的无冲突路由；
   - 补充包含嵌入式 HTML、本地图片、代码与媒体的示例目录及对应端到端验收项。
4. **阶段 4：声明式配置驱动、热重载、治理三件套与开发工作流提效扩展（已落地）**
   - 落地 `-c/--config`（`D_CONFIG`）纯 `std` JSON 清单解析、`SIGHUP` 全量预检增量热重载与 `/readyz` 探针，实测无关长连接（SSE/WS）热重载不断流；
   - 交付零外依治理三件套（`ext-observability`、`ext-ratelimit`、`ext-auth`）、开发工作流提效套件（`ext-dev-kit`）、`app-files` 多前缀/多 Host 挂载及 `doc-render` `sanitize_html`。
5. **阶段 5：纯 Rust TLS、WebSocket / 原生 TCP、通用反向代理与 `d-*` crates.io 命名空间发版就绪（已落地）**
   - 交付 `d-tls-api` + `d-l4-tls`（SNI/ALPN/原子热换证，零 `cargo audit` 警告）、`d-ws-api` + 纯 Rust RFC 6455 `d-proto-ws`、`d-proto-tcp` 与 `d-proxy-api` + `d-ext-proxy`（Keep-Alive 池、三种 LB、主被动健康检查、RFC 7239 `Forwarded`、SSE 穿透与 WS 隧道）；
   - 将非 `d-*` 前缀的 26 个子包统一规范为 `d-*` 命名空间并升版至 `0.1.1`（全部 31 个待发布包 + `xtask` 设为 `publish = false`），通过跨平台 CI（Linux/macOS/Windows）、32 包架构检查与独立干净重建。
